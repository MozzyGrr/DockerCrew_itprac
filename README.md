## 3. Требования и проверки

| ID | Тип | Требование и условия | Способ проверки | Статус/источник |
|---|---|---|---|---|
| F-01 | Функциональное | Пользователь видит список событий: название, дата, место, число свободных мест | Сравнить ответ с тестовыми событиями | Факт |
| F-02 | Функциональное | Пользователь регистрируется на событие со свободными местами, получает ID регистрации, число свободных мест уменьшается | Зарегистрироваться, найти регистрацию по ID, сверить счётчик | Факт |
| F-03 | Функциональное | Пользователь отменяет свою регистрацию, место освобождается | Отменить, проверить, что регистрация не активна и счётчик вырос | Факт |
| N-01 | Нефункциональное | Мест не занято больше лимита: 50 одновременных попыток на событие с 10 местами дают ровно 10 успешных регистраций | Параллельный тест с известным набором данных | Допущение (нужно подтвердить жёсткий лимит) |
| N-02 | Нефункциональное | Повторная регистрация того же пользователя на то же событие не создаёт дубль | Отправить запрос дважды, сравнить число записей | Допущение |
| N-03 | Нефункциональное | Регистрация сохраняется после пересоздания приложения | Зарегистрироваться, пересоздать контейнер, прочитать и сравнить | Факт |
| N-04 | Нефункциональное | При потере узла с БД: RPO ≤ 1 ч, RTO ≤ 30 мин | Испытание восстановления с замером времени | Факт |
| N-05 | Нефункциональное | Другой человек разворачивает сервис на чистой ВМ по репозиторию и документации | Развёртывание по инструкции | Допущение |
| N-06 | Нефункциональное | Есть панель и оповещение, в том числе по росту ошибок регистрации | Вызвать сбой, увидеть оповещение | Допущение |

Исходное ожидание по сохранности данных: Данные пользователей сохраняются при сбоях
Согласованное ограничение учебного стенда: При потере узла с БД: RPO ≤ 1 ч, RTO ≤ 30 мин
Сценарий отказа, для которого заданы RTO и RPO: Синтетические данные, пригодная копия, доступная среда восстановления
